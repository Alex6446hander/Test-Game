# Лабораторная работа №3: Декомпозиция микросервисной системы
Предметная область: Геймифицированный трекер навыков и привычек (Skill Tree & Habit RPG).

## 1. Описание предметной области, акторы, сценарии
Описание: Система превращает саморазвитие в RPG-игру. Пользователи создают «Древо навыков», привязывают к узлам реальные привычки. Выполнение привычек приносит опыт (XP) и монеты, которые тратятся на открытие новых навыков или виртуальные награды.
Актёры: Пользователь (Player), Внешний сервис геймификации (например, API достижений).
Пользовательские сценарии:
1. Как пользователь, я хочу завершить ежедневную привычку, чтобы получить XP и повысить уровень своего навыка.
2. Как пользователь, я хочу обменять накопленные монеты на награду (например, "Час отдыха"), чтобы мотивировать себя.
3. Как пользователь, я хочу видеть прогресс-бар навыка, чтобы понимать, сколько осталось до его улучшения.

## 2. Доменные события и ограниченные контексты
Доменные события:`HabitCompleted`, `LevelUp`, `RewardPurchased`, `RewardPurchaseFailed`.
Ограниченные контексты:**
- Profile (Профиль):`PlayerStats` (общий уровень, глобальный XP), `SkillNode` (конкретный навык и его уровень).
- Quest (Задачи):`Habit` (регулярная задача), `CompletionLog` (история выполнений с гибкой структурой).
- Reward (Награды):`VirtualCurrency` (баланс монет), `InventoryItem` (купленные бонусы).
- Notification (Уведомления):`AlertTemplate` (шаблоны сообщений о повышении уровня).

## 3. Карточки сервисов и отвергнутые варианты
| Название | Ответственность | Владеет данными | Предоставляет | Зависит от | Обоснование границы |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `profile-service` | Управление уровнями, XP и древом навыков. | `PlayerStats`, `SkillNode` | REST API, событие `LevelUp` | `quest-service` (синхронно) | Требует строгой ACID-транзакционности при изменении XP. Вычислительно затратен при пересчете дерева, поэтому выделен отдельно. |
| `quest-service` | Управление привычками и фиксация их выполнения. | `Habit`, `CompletionLog` | REST API, событие `HabitCompleted` | `profile-service` (синхронно) | Высокая частота записи (пользователь отмечает задачи десятки раз в день). Требует гибкой схемы для разных типов привычек. |
| `reward-service` | Управление виртуальной экономикой и инвентарем. | `VirtualCurrency`, `InventoryItem` | REST API, событие `RewardPurchased` | `profile-service` (синхронно) | Требует сверхбыстрых операций (проверка баланса, списание), часто подвержен попыткам "двойной траты" (race condition). |
| `notification-service`| Отправка push/email уведомлений о достижениях. | `DeliveryLog` | REST API (internal) | События: `LevelUp`, `RewardPurchased` | Не критичен к задержкам. Сбой не должен влиять на начисление XP или монет. |

**Отвергнутый вариант:** Объединение `profile-service` и `reward-service` в один `economy-service`. Отказались, так как логика начисления XP (математика прогрессии) и логика транзакций валюты (блокировки, защита от фрода) имеют разные требования к консистентности и масштабируемости.

## 4. Таблица выбранного ПО
| Компонент | Кто использует | Обоснование выбора |
| PostgreSQL | `profile`, `notification` | Строгие транзакции (ACID) критичны для корректного начисления XP и уровней. |
| MongoDB | `quest` | Гибкая схема (BSON) идеальна для хранения разных типов привычек (текст, чек-листы, таймеры) без постоянных миграций. |
| Redis | `reward` | Сверхбыстрые атомарные операции (INCR/DECR) для баланса монет и защита от race condition при покупках. |
| RabbitMQ | Все бизнес-сервисы | Гарантированная доставка событий. Поддержка Dead Letter Queue (DLQ) для обработки сбоев без потери данных о выполнении привычек. |
| Nginx | API Gateway | Маршрутизация, SSL, базовый rate limiting для защиты от спама отметками привычек. |

## 5. Схема взаимодействий и таблица
*(См. файлы `docs/architecture.png` и `docs/sequence-saga.png`)*
Таблица взаимодействий:
1. `client` → `quest-service` (sync, `POST /api/v1/habits/{id}/complete`): Отметить привычку выполненной.
2. `quest-service` → `profile-service` (sync, `GET /internal/profile/{id}/skills`): Проверить, дает ли эта привычка XP для конкретного навыка.
3. `reward-service` → `profile-service` (sync, `GET /internal/profile/{id}/level`): Проверить уровень перед покупкой награды, требующей мин. уровня.
4. `quest-service` → `profile-service`, `reward-service` (async, `HabitCompleted`): Начислить XP и монеты.
5. `profile-service` → `notification-service` (async, `LevelUp`): Поздравить пользователя.

## 7. Сценарий сбоя
Сценарий: Выполнение «Босс-квеста» (сложной привычки), который дает много XP и уникальный предмет в инвентарь.
1. `quest-service` помечает квест как выполненный и публикует `HabitCompleted`.
2. `profile-service` получает событие и успешно начисляет +500 XP.
3. `reward-service` получает событие и пытается выдать уникальный предмет.
4. СБОЙ:** Предмет закончился на складе (бизнес-ошибка) или Redis недоступен. `reward-service` публикует `RewardPurchaseFailed` с `correlationId`.
5. Компенсация:** `profile-service` слушает этот топик, находит транзакцию по `correlationId` и *списывает* ранее начисленные +500 XP (откат состояния). `quest-service` возвращает квесту статус `AVAILABLE`.
6. Система остается в согласованном состоянии: пользователь не получил награду и не получил за нее XP.
